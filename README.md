## 它能干什么

一句话：**在浏览器靶场里量你第一次甩枪是系统性过头还是不到位，用自适应阶梯收敛，再用盲测 A/B 排除安慰剂；测出来的 `cm/360` 一键流到 20 款游戏的等效表，并用一条短码在电脑和手机之间同步。**

| | 做什么 | 产出 |
|---|---|---|
| **① 主测试** | pointer lock 原始输入复刻端瓦相机，甩枪 → 偏差 → 收敛 → 盲测 | 推荐 `cm/360` + 置信度 |
| **② 报告** | 收敛曲线、过头/不足、盲测结论、全部原始甩枪记录、本机历史 | 可导出 JSON |
| ③ 交叉验证 | 追踪压靶 15s / 微修正 20s（不改推荐值） | 偏科提示 |
| ④ 换算 | 基准配置、目标游戏、DPI 变更、手感微调 | 可直接填进游戏的数值 |
| ⑤ 等效表 | 20 款内置 + 自定义游戏，可搜索、可复制 | 一张全量表 |
| ⑥ 共享 | `?s=SL2.…` 链接 / 分享码 / 本地二维码 | 约 84 字符配置 |
| ⑦ 扩展 | 靶场实测反推任意网游的 `yaw` | 加入换算体系并随分享码同步 |

## 快速开始

### 本地直接用

双击 `index.html`。无需安装、无需构建、无需联网——所有计算、画布和二维码都在浏览器本地完成。

> 本地打开时分享链接是 `file://` 路径，只在本机有效。跨设备请复制「分享码」到另一端粘贴，或按下面部署到 Pages 后扫码。

### 部署到 GitHub Pages

```bash
git clone https://github.com/<你的用户名>/<仓库名>.git
cd <仓库名>
cp /path/to/sens-sync/{index.html,README.md,LICENSE,tests.mjs} .
git add . && git commit -m "feat: SensLink 个人灵敏度实验室" && git push origin main
```

仓库 **Settings → Pages → Deploy from a branch → `main` / `root` → Save**，稍等即可访问
`https://<用户名>.github.io/<仓库名>/`。Cloudflare Pages / Vercel / Gitee Pages 同样可用，都是纯静态托管。

### 自测

```bash
node tests.mjs
# 44 项通过：换算公式、20 款游戏的 yaw 表、短码编解码、
# 靶场三个纯函数（首次子运动 / 自适应阶梯 / 盲测）、页面结构与 DOM 引用
```

## 完整流程

### 0 · 先把测量环境弄干净（最关键的一步）

- Windows 指针速度 **6/11**，关闭「提高指针精确度」；
- 鼠标驱动里关掉一切加速 / 平滑；浏览器缩放 **Ctrl+0** 回 100%；
- 用你平时打游戏的那只鼠标和那块鼠标垫，握法别临时改；
- HUD 会显示是否拿到原始输入（⚠ 表示没有）。此时点「校准鼠标计数 / DPI」：沿尺子单向平移 **10 cm** 后点击一下，工具算出每厘米上报计数并给出补偿系数。

环境不干净，测的就是操作系统的指针缩放，不是你的手臂。

### 1 · 主测试（约 8–10 分钟）

填 DPI、起始 `cm/360`（默认取你当前配置）、搜索范围、每轮甩枪数 → 「进入靶场 · 开始测试」。

靶子出现后，**一次快速甩过去并点击，不要慢慢修正**——算法量的是第一下弹道挥动。前 3 个靶热身不计分，每轮 8 次有效甩枪；一轮结束显示中位偏差、过头/不足次数，并自动切到下一档 `cm/360`。收敛后进入盲测 A/B。

> ESC 暂停，进度不丢；「清空测试进度」只清当前会话，历史记录保留。

### 2 · 看报告

推荐 `cm/360`、你 DPI 下的端瓦灵敏度、eDPI、收敛轮次、过头/不足、盲测结论与置信度、收敛曲线、每一次甩枪的原始记录（可导出 JSON），以及本机历史表。

报告里写死了几条纪律，**照做比多测十次更有用**：

- 这是**今天、这套桌椅鼠标垫下**最顺手的甩枪值，不是永久最优；
- **同一天测 2~3 次、方向一致**才采信，历史表就是用来看这个的；
- 填进游戏后**至少打 10 局、固定用一周**再评价。任何新灵敏度头一小时都会觉得别扭；
- 一两发命中、零点几 `cm/360` 的差异是噪声，别追。「固定一个月」往往比再找一个更准的数字提升更大。

### 3 · 交叉验证（可选）

点「追踪压靶」或「微修正」。结果写进报告但**不改推荐值**：抖动明显通常偏快，修正拖沓通常偏慢，用来判断你是不是为了甩枪牺牲了稳定性。

### 4 · 一键流到换算（次要功能）

点「把测试结果设为换算基准」，基准卡、目标游戏结果、全游戏等效表全部联动。也支持手动改基准、一键换 400/800/1600 DPI 不掉手感、拖滑杆预览 ±30% 手感、显示游戏内小数位取整带来的 `cm/360` 偏差。

### 5 · 跨端共享

配置压进约 84 字符短码，三种携带方式：

| 方式 | 适用场景 |
|---|---|
| `?s=SL2.…` 分享链接 | 部署后，电脑生成、手机扫码打开即还原 |
| `SL2.…` 分享码 | 微信 / 备忘录粘贴，另一端「载入配置」 |
| 本地二维码 | 浏览器本地绘制，断网也能生成 |

手机端**只能查看报告、换算和携带配置，不能实测**——触屏没有 DPI 和原始鼠标计数概念，页面会直接禁用测试按钮并说明原因。本机还能存多套配置、导出 JSON。

## 方法论：为什么不信「手感」

最近「调灵敏度」的工具大致三类，前两类都有一个共同问题：**问的是感觉，量不到东西**。

| 做法 | 代表 | 局限 |
|---|---|---|
| 主观对比 / PSA 二分法 | PSA Method、PerfectTenzivity | 「哪个更舒服」极易被适应污染——任何值用两天都会觉得舒服；固定 7 轮迭代也不够精细 |
| 只看命中率 / 分数 | 各类 aim trainer | 分数受反应、时机、压枪、目标大小影响，灵敏度只是其中一项 |
| **量首次甩枪落点 + 自适应收敛 + 盲测** | AimFinder、XBitLabs、VALORANT 灵敏度选择器 | 目前最经得起推敲的路子 |

SensLink 走第三条，并把「测完之后怎么用」补齐。四步：

1. **相机 1:1 复刻** — pointer lock 原始输入（`unadjustedMovement`），每个鼠标计数转 `0.07° × sens`，水平 FOV 103°（16:9）。在这里甩 180° 的手部位移和在端瓦里一样。
2. **度量：首次弹道子运动偏差**（first-submovement bias）— 快速瞄准 = 一次不靠视觉反馈的弹道挥动 + 之后的小修正。切出第一段轨迹，拿终点与靶子实际角度比，得到有符号偏差：**正 = 冲过头（偏快）**，**负 = 没到（偏慢）**。单发很噪，一个 block 的中位数才是信号。
3. **搜索：自适应阶梯** — 按偏差方向把 `cm/360` 往减小偏差的方向推，方向反转就收缩步长；两次反转且偏差落进噪声带，或达到 10 轮，判收敛。用 `cm/360` 而不是游戏内数值做变量，是因为它有物理意义、跨游戏通用。
4. **验证：盲测 A/B** — 推荐值与 ±12% 诱饵随机排成 A、B 各打 6 靶，界面隐藏数值，用「偏差绝对值中位数 + 命中数」判定。**推荐值没赢就如实报「无显著差异，保持原值」**，不粉饰算法。

与同类实现的差异：偏差与「点击命中」分开记录（玩家修正后点中靶，偏差依然如实留下）；盲测结论、置信度、以及「没测出差异」都会写进历史；测试结果和换算配置共用同一套短码。

## 算法与公式

三个纯函数挂在 `window.SensLabCore`，`tests.mjs` 会直接把它们从 `index.html` 抽出来跑，避免测试和实现各写一份公式。

```js
// 1) 切出第一次弹道子运动：越过 25% 距离后遇到明显反向或 >85ms 停顿即收尾
analyzeFlick(samples /* [{t,d}]，d 已按目标方向归一化 */, targetDeg)
// → { bias:(endpoint-targetDeg)/targetDeg, endpoint, clean, duration }

// 2) 自适应阶梯（变量是 cm/360）
staircaseStep({cm, lo, hi, step:0.18, reversals, lastDir, rounds, noise:0.06, maxRounds:10}, medianBias)
// bias > +0.06 → cm *= (1+step)   过头，调慢
// bias < -0.06 → cm *= (1-step)   不足，调快
// 方向反转 → step *= 0.62；噪声带内且 reversals>=2 或 rounds>=10 → converged

// 3) 盲测判定
blindVerdict(A, B)  // A/B = {biases:[], hits}
// 主看 |bias| 中位数，命中率次之；gap < 0.02 且命中率差 < 0.25 → tie / 低置信度
```

相机与跨游戏换算共用同一个物理锚点：

```
degPerCount = 914.4 / (DPI × cm/360) × calibScale        # 914.4 = 360° × 2.54 cm/inch
视角角变化   = movementX × degPerCount
屏幕 x       = W/2 + tan(rel°) / tan(103°/2) × W/2

cm/360       = 914.4 ÷ (DPI × sens × yaw)
目标 sens    = 源 sens × 源 yaw × 源 DPI ÷ (目标 yaw × 目标 DPI)
```

`calibScale = (DPI / 2.54) / 实测计数每厘米`，用于补偿没拿到原始输入时系统的指针缩放。

**yaw 数据分级**（界面会打标签，不把不确定的数伪装成精确值）：

- **已核对**：瓦 0.07；CS2 / CS:GO / Apex / 三角洲 / KovaaK's / ARC Raiders 0.022；OW2 / CoD / 命运 2 0.0066；堡垒之夜 0.005555；R6 0.00572958；漫威争锋 0.0175；Deadlock 0.044；塔科夫 0.125；Aim Lab 0.05。
- **近似**：战地 6、Roblox。
- **参考 / 公开数值冲突**：PUBG、Rust、The Finals（The Finals 有 0.001 与 0.0044 两说，PUBG 有 0.002222 与 0.022 两说）。只当起点，**必须进靶场实测一整圈校准**。

**添加任意网游**：不猜系数。关掉加速，贴尺子匀速横移直到视角正好转满 360°，把位移填进 ⑦ 区，工具用 `yaw = 914.4 ÷ (DPI × sens × cm)` 反推并加入体系，也会随分享码同步到手机。

## 常见问题

**为什么不直接问「哪个手感好」？**
因为任何数值用两天都会变舒服，那是适应不是性能。这里量的是第一次甩枪落点，不问感受。

**结果每次都不一样，是不是坏了？**
一两发命中、零点几 `cm/360` 的波动是正常的。同一天测 2~3 次，方向一致才采信；如果几轮一直互相矛盾，诚实的答案是「这个差异对你不重要」，保持原值。

**盲测说「无显著差异」怎么办？**
保持你原来的设置。工具不会为了给出一个漂亮结论而强行推荐新数值。

**手机能测吗？**
不能，触屏没有 DPI / 原始鼠标计数。手机端用于查看报告、换算、扫码携带配置；实测必须在电脑端用鼠标完成。带触摸屏的笔记本只要有鼠标，仍可测量。

**多久重测一次？**
换鼠标、鼠标垫、握法，或状态明显漂移时重测。别在同一个数字上来回微调——固定使用比反复寻找提升更大。

**会读写我的游戏配置文件 / 上传数据吗？**
不会。纯静态网页，不读写本地文件，二维码由浏览器本地绘制。想「一键写进游戏 cfg」，可把数值配合 [Autosens](https://github.com/sillynov/autosens) 使用。

**Firefox / Safari 能用吗？**
可以，但部分浏览器不给 `unadjustedMovement`。HUD 提示 ⚠ 时先做「校准鼠标计数 / DPI」，否则测量结果会被系统指针缩放污染。

## 诚实的边界

- **只测腰射甩枪**。追踪、压枪、身法、开镜倍率、每英雄独立灵敏度、FOV 观感都不在主测试结论里；两个交叉验证只做提示，不参与收敛。
- **浏览器不是游戏客户端**。相机数学一致，但渲染与输入延迟不同；这里的绝对分数只能在本工具内部比较，不能与游戏内统计对照。
- **需要鼠标 + 桌面浏览器**，触控板结果没有意义。
- **手机端不测**，只查看与携带。
- 换外设或状态明显漂移时重测；推荐值是**起点**，需要实战验证并固定使用一段时间。

## 仓库结构与二次开发

```
index.html              主程序（HTML + CSS + JS + 内嵌二维码库，全单文件，约 99 KB）

preview-arena.png       全屏靶场预览

LICENSE                 MIT
```

- **改游戏表**：编辑 `index.html` 里的 `GAMES` 数组，每项 `{id, name, yaw, dec, unit, lv, note}`；`lv` 取 `verified | estimate | disputed`，界面会显示对应标签。
- **改测试参数**：`analyzeFlick` 的 `gapMs / minFrac`、`AR.st` 的 `noise / step / maxRounds`、盲测诱饵比例，都在「靶场：纯算法」一段。
- **开放接口**：`window.SensLabCore` 暴露三个纯函数与相机换算，`window.SensLabState` 暴露实时测试状态，方便二次开发或接入自己的训练流程。
- **旧链接兼容**：`SL1.` 分享码仍可读取，新码统一 `SL2.`（紧凑数组 + UTF-8 Base64URL）。
- 二维码使用内嵌打包的 [qrcode.js](https://github.com/soldair/node-qrcode) v1.5.4（MIT，Ryan Day），**不依赖任何 CDN**。

欢迎提 issue / PR：新增游戏的可靠 yaw、新的测试场景、多语言、以及任何对方法论的质疑，都比加一个皮肤更有价值。
